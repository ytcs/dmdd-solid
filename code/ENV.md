# Ab initio environment (2026-11-01; user directive: run computations that fit this box and finish relatively quickly; formulate the rest)

**Rebuild:** `bash code/setup-env.sh` (micromamba → conda-forge `qe=7.6` with openmpi 5.0.11, openblas 0.3.34, fftw 3.3.11, scalapack 2.2.0; SG15 ONCV pseudopotentials).
**Run every heavy job through `code/run-heavy.sh <LABEL> <cmd…>`** (flock on /root/heavy.lock: one heavy job at a time on the 4 cores; log /root/heavy.log). It sets PATH to /root/mamba/envs/qe/bin and the OpenMPI root variables. Use `mpirun -np 4`, OMP_NUM_THREADS=1.

- Codes: pw.x, ph.x, q2r.x, matdyn.x, epw.x, turbo_*.x, hp.x, projwfc.x (QE 7.6). Never `/usr/bin/pw.x`: the Ubuntu QE 6.7 package aborts at start-up ("buffer overflow detected") and was removed.
- **Campaign fork: github.com/ytcs/qe-rtsc** (branch `rtsc`, from the `qe-7.6` tag; EPW in tree; user: "our custom optimized version"). Its speedups are GPU-only (nvfortran/CUDA: batched Sternheimer engine `rtsc/sth`, `RTSC_STH=1`; EPW coarse/fine/Eliashberg GPU kernels `rtsc/epw`); the one CPU-side change (wannier90 disentanglement over OpenMP, `RTSC_W90_NT`) is bitwise identical to vanilla. On this CPU box the fork reduces to vanilla 7.6, so the conda-forge QE 7.6 build is used here with identical numerics. **Every FORMULATED (over-limit) job targets the fork on GPU:** write its inputs in the `rtsc/bench` layout (`@PSEUDO@` placeholder, SG15 via `rtsc/pseudo.sh`, stages as in `rtsc/bench/run-fork.sh`), so they run unchanged on the user's pod.
- **Pseudopotentials (campaign standard):** SG15 ONCV PBE, scalar-relativistic, version 1.2 where available (else highest), norm-conserving (ph.x and EPW compatible). Tarball sg15_oncv_upf_2020-02-06.tar.gz, sha256 3f3bd74aa5d6e0b038218a6051bb99ed9469dc03d0f05b3ec8a523f0f7a7dff0, URL in setup-env.sh. Fully relativistic `_FR` files only for SOC runs. Record the exact file per species in each job's inputs. Do not use the QE-library Si.pz-vbc (smoke test only).
- **Benchmark (loaded box, 9 agents running):** Si 2-atom, ecut 20 Ry, 8³ k: SCF 2 s; DFPT 4×4×4 q grid 3.5 min. Converged ecut (≈ 60–80 Ry for SG15) costs ≈ 5–10× more.
- **Job limits (coordinator default, pending user confirmation):** ≤ 3 h wall and ≤ 12 GB RAM per job; disk ≤ 10 GB scratch. A job estimated above that is FORMULATED only (inputs, grids, cost estimate) for the user's larger compute.
- **Where things live:** work directories (outdir, *.save, wavefunctions, EPW .epb/.wfc) in /root/work/<ID>/ only — never under campaign/. Commit only inputs, scripts, small outputs (dyn, frequency tables, band edges, convergence tables) in code/<ID>/.
- **Provenance tag [CALC]** (CONVENTIONS R13 amendments): a value computed here, with code/<ID>/ holding inputs, pseudopotential names, the convergence record and the CONTROLS case it passed.
- **Phonon/charge transport Monte Carlo: github.com/ytcs/CMPMC** (user: "our ported G4CMP"; commit 921db93). Header-only C++20 port of G4CMP physics without Geant4 (anisotropic phonon kinematics, Tamura down-conversion and isotope scattering, Herring–Vogt electron valleys and holes with NTL emission, intervalley scattering, trapping, Kaplan films / 3D Bogoliubov QPs, FEM fields, electrode masks; presets Si, Ge, Al₂O₃, CaWO₄, SiO₂, GaAs, CaF₂, LiF, Al, Nb, Cu). Build: `git clone --depth 1 https://github.com/ytcs/CMPMC /home/user/ytcs/CMPMC && cmake -B /root/cmpmc-build -DCMAKE_BUILD_TYPE=Release -S /home/user/ytcs/CMPMC && cmake --build /root/cmpmc-build -j2` (g++ 13.3, cmake 3.28). Benchmark on the loaded box: 4.4 M phonon steps/s, energy conserved (examples/phonon_benchmark). Multi-thread runs go through code/run-heavy.sh like QE. Physics constants/presets used in a campaign number must be quoted from the CMPMC source with file:line and checked against the cited literature.
