# Three-volume edition: corrections of errors found during the edit

User directive (2026-11-12): "also fix all the errors, inconsistency and derivation mistakes we found along the way, these corrections should undergo proper review process though".

During the chapter passes and the end-to-end volume reviews, editors were told to change no equation, number, symbol or citation, and to list instead every error, inconsistency and suspected derivation mistake they saw. This stage corrects them, with review.

## Stages
1. **Harvest** (one agent). Read every log and notes file in book/ledgers/REVIEWS/volumes/ (unit logs, E2E logs, E2E notes, structure findings) and the lead's list /tmp/claude-0/-home-user-dmdd-solid/d1725f47-7573-51dd-bf4b-00f15cc471f7/scratchpad/followups.md. Write book/ledgers/REVIEWS/volumes/ERRATA.md: one entry per distinct problem, with an id (ER-1, ER-2, …), every location (file:line, label), the conflicting statements quoted exactly, who reported it, and a category: VALUE (one quantity, different values), DERIVATION (a step, factor, sign or limit that may be wrong), CITATION (wrong source, equation number or attribution), DEFINITION (one symbol or quantity defined two ways), TEXT (a statement that the text elsewhere contradicts). Merge duplicates. Exclude pure layout, wording and structure items (those are handled elsewhere).
2. **Correction proposals** (one agent per group of entries, grouped by chapter or topic). For each entry, establish the truth from primary evidence: the cited source (full texts are extracted in book/sources/ and the bibliography is tex/bib/book.bib; fetch with /home/user/dmdd-solid/skills/breakthrough-maths/scripts/lit.py if needed), the figure or number script behind a value (book/figscripts/, /home/user/dmdd-solid/code/; rerun if it runs in minutes), and an independent re-derivation for a derivation item. Write a proposal under the entry in book/ledgers/REVIEWS/volumes/errata/<group>.md: the correct statement, the evidence (source and equation, script and output, or the derivation written out), the exact old → new text for every location, and which other numbers move with it (grep for every use of the value and of results computed from it). If the evidence does not settle it, say so and propose "no change" or the most defensible wording. Do not edit the tex.
3. **Independent review** (a different agent per group, who has not seen the proposer's work beyond the proposal file). For each proposal, check the evidence yourself (open the source at the cited equation, rerun the script, redo the derivation), and give a verdict: ACCEPT, AMEND (with the amended text and why) or REJECT (why). Write the verdict under the proposal.
4. **Apply** (the proposer of the group, after review). Apply ACCEPTED and AMENDED corrections exactly, and nothing else; chapcheck every touched chapter; lint; mark each entry APPLIED with the commit-free file:line list. Rejected entries stay listed with the reason.

## Rules
- A correction changes only what the evidence requires. Downstream numbers computed from a corrected value are recomputed by their script, not scaled by hand, unless the dependence is exactly linear and stated.
- When two values are both right for different settings (e.g. two calibrations, two functionals), the correction is to say which is which, not to unify them.
- Language rules of COMMON.md (Addendum 1) apply to any new wording.
- Never use git stash, checkout or reset; never edit outside the files an entry names.
